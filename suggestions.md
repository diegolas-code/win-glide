# Suggestions for win-glide

## Summary
- Clean, well-structured Rust project matching the stated spec (keyboard-driven, momentum-based window movement).
- Layered architecture: `input`, `platform`, `physics`, `app`, `ui`, `window`, `config`.

## Strengths
- Clear physics model in `src/physics.rs`.
- Proper separation of concerns and use of `tiny-skia` for overlay rendering.
- Resource cleanup via `Drop` implementations for hooks and hotkeys in `src/input.rs`.
- DPI and multi-monitor awareness in `src/platform.rs`.

## Risks / Caveats
- `InputManager::run_loop` blocks on `GetMessageW` and lacks an explicit quit path; hooks/hotkey may remain until process exit.
- System-level tests register real hooks/hotkeys; these can be flaky or fail in CI and when resources are already taken.
- `keyboard_proc` consumes non-modifier keydowns to suppress target-window input during a session; this could conflict with global shortcuts if not carefully scoped.
- `EVENT_SENDER.set(...)` ignores errors silently if already set, hiding potential event-delivery issues.
- Overlay creation assumes straightforward pixel layout/stride; unusual drivers/displays might expose bugs.
- Global hooks and `RegisterHotKey` may fail in restrictive or sandboxed environments.

## Recommendations (low effort)
- Add a graceful shutdown path for the input thread (PostThreadMessage/WM_QUIT or a thread stop signal) so hooks and hotkey unregistration always run.
- Mark system-level hook/hotkey tests with `#[ignore]` or gate them behind an integration-test feature to avoid CI flakiness.
- Log and/or handle failures from `EVENT_SENDER.set(...)` and from `Config::save()`/`load()` to make debugging easier.
- Add defensive checks and logging around `CreateDIBSection`, the DIB pointer, and `UpdateLayeredWindow` in `src/ui.rs`.
- Document testing caveats and the need for an interactive Windows desktop session in `README.md`.

## Suggested next steps
- Implement graceful input-thread shutdown (small focused change).
- Adjust or gate system-level tests to avoid CI failures.
- Optionally, add a short developer note to `README.md` documenting testing and shutdown behavior.
